# Noctra

AI-powered business-news intelligence: each headline is analysed through SWOT, PEST and Diamond-E lenses, then mapped as a causal graph so you see *what* happened and *what it drives*.

## Demo

[Live application → https://noc-tra.cc/](https://noc-tra.cc/)

> **Screenshots & GIFs** — Visual captures of Aperçu (the briefing deck) and Catographic (the event graph) should be added to `docs/screenshots/` and linked here so a recruiter can grasp the project in 20–30 seconds.

## Features

- **Aperçu** — A scrollable briefing deck of the last 7 days of CNBC headlines. Every card carries an executive summary, a SWOT, a PEST and a Diamond-E analysis generated by a reasoning model.
- **Catographic** — An interactive force-directed graph of the most connected events. Hover to isolate a node and its neighbourhood; click an edge to read the model’s argument for why one event drives another.
- **Verified linkages** — A reasoning model (o4-mini) reads two full articles and decides whether a causal link exists. Rejected pairs are stored so the pipeline never pays twice for the same negative verdict.
- **Admin observatory** — A private `/admin` floor for linkage curation, article correction, graph-tuning (window size, strength floor, node limit) and pipeline health monitoring.
- **Graceful degradation** — If Supabase is unreachable the page renders an empty state rather than failing the build, so a deploy during an outage does not take the site down.

## Technical highlights

- **Server Components over API routes** — Pages query Supabase directly via the TypeScript client; one less hop, no hardcoded backend origin to break in production.
- **Three-layer admin gate** — Proxy redirect + layout server check + RLS `is_admin()` policy + individual Server Action guards. The action is a public POST endpoint, so it defends itself even if middleware is bypassed.
- **Force-directed layout, client-side** — Graph positions are computed with `d3-force` in `lib/layout.ts` so `get_graph()` returns pure data. Dagre was abandoned because strict left-to-right ranks become an unreadable ribbon past ~20 nodes.
- **RLS + grants, not RLS alone** — Column-scoped `UPDATE` for the pipeline role; `DELETE` and `TRUNCATE` are revoked from every API role including `service_role`. Retiring a linkage is `is_linked = false`.
- **Settings-driven tunables** — `MIN_LINK_STRENGTH` and `GRAPH_WINDOW_DAYS` live in `public.settings` rather than code. They have each blanked a public page once before; now they can be changed from `/admin/settings` without a redeploy.
- **Hourly GitHub Actions pipeline** — Fetch → Analyse → Embed → Discover linkages → Generate insights. Runs on a free cron schedule; the hourly activity also keeps the free-tier Supabase project awake.

## Architecture

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   Next.js App   │────▶│    Supabase      │◀────│  Python Pipeline │
│  (Vercel Hobby) │     │  Postgres+vector │     │ (GitHub Actions) │
└─────────────────┘     └──────────────────┘     └─────────────────┘
        │                        │                        │
        ▼                        ▼                        ▼
   App Router              articles                    OpenAI
   Server Components       linkages                    feedparser
   React Flow              article_insights            text-embedding-3-small
   d3-force (layout)       public.settings             o4-mini / gpt-5.4-mini
```

The frontend is **Next.js 16 App Router** with React 19, deployed on Vercel. Server Components read Supabase directly; there are no API routes.

The database is **Supabase** (Postgres 15 + pgvector). Two RPCs do the heavy lifting: `match_articles(...)` for vector candidate search and `get_graph(p_days, p_node_limit)` which returns React-Flow-shaped `{nodes, edges}` in one round trip.

The **Python pipeline** runs hourly in GitHub Actions. It fetches CNBC headlines, analyses them through business frameworks, generates embeddings, discovers causal linkages via an all-pairs verifier, and writes event summaries with future predictions. It authenticates via a custom JWT minted for the `pipeline_writer` Postgres role.

## Local development

### Frontend (Next.js)

```bash
# 1. Install dependencies
npm install

# 2. Create environment file from the example
cp .env.example .env.local
# Fill in NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY

# 3. Run the dev server
npm run dev        # http://localhost:3000
```

### Pipeline (Python)

```bash
# 1. Create the pipeline virtual environment
python -m venv .venv-pipeline
source .venv-pipeline/bin/activate

# 2. Install dependencies
pip install -r pipeline/requirements.txt

# 3. Create pipeline environment file
cp pipeline/.env.example pipeline/.env
# Fill in SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_PIPELINE_TOKEN, OPENAI_API_KEY

# 4. Run stages sequentially
python pipeline/fetch_news.py
python pipeline/analyse_news.py
python pipeline/embed_articles.py
python pipeline/discover_linkages.py --days 7 --max-verify 100
python pipeline/generate_insights.py --top 10
```

### Database types

```bash
npm run types      # regenerates lib/database.types.ts from the linked Supabase project
```

## Limitations and future work

- **AI output is informational, not authoritative.** Every analysis is generated by a language model and can be wrong. Each card keeps its original source one click away so claims can be verified.
- **No duplicate-news detection.** The same story published under different headlines will be ingested as separate articles.
- **No retry or rate-limit handling.** A transient OpenAI or network failure during the pipeline can drop stories for that hour.
- **No background task queue.** The pipeline runs as a linear GitHub Actions job; a failure in one stage stops the rest.
- **No tests.** Ingestion and analysis failures are not caught by automated tests.
- **Free-tier Supabase pauses after ~7 days idle.** The hourly pipeline keeps it awake, but if the cron is disabled the project will sleep.
- **Cosine similarity is anti-correlated with causal insight.** The current all-pairs verifier is expensive; the promising direction is embedding a causal fingerprint (drivers/exposures) rather than prose similarity.
- **Superseded code still present.** The Django backend (`backend/`) and Vite frontend (`frontend/`) will be removed once the Next.js stack is fully verified live on Vercel, along with `Dockerfile`, `docker-compose.yml`, `requirements.txt` (root) and `start_local.sh`.
